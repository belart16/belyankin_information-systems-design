# Fitness-center - проектирование информационной системы

**Выполнил:** Белянкин Артемий Русланович<br>
**Группа:** БИ 3-3

**Кейс:** система управления программой лояльности сети фитнес-клубов «Fitness & Health» - клубные карты, фитнес-баллы, вознаграждения, запись на тренировки, интеграции (платёжный шлюз, фискальная система, фитнес-трекеры).

## Структура репозитория

| Папка/Файл | Содержимое |
|---|---|
| `case/` | Исходный кейс и чек-лист |
| `lr_01-class-model/` | ЛР №1. Концептуальная модель классов (глоссарий, диаграмма классов, диаграммы объектов) |
| `lr_02-use-cases/` | ЛР №2. Модель вариантов использования (акторы, 33 варианта использования, диаграмма ВИ) |

| `lr_04-use-case-specification/` | ЛР №4. Спецификация вариантов использования (приоритизация, каталог бизнес-правил, 4 спецификации, диаграммы деятельности) |
| `lr_05-interaction-model/` | ЛР №5. Модель взаимодействия (раскадровка экранных форм, системные диаграммы последовательности, спецификации системных операций, сценарии тестирования) |

| `fitness.modlr` | Модель MDriven Designer (ЛР №3, OCL) - лежит в `lr_03-model-refinement-ocl/` |

## Методология и инструменты

- **Подход:** ICONIX (use-case driven) - от требований к коду через минимум UML-диаграмм.
- **Теория:** Розенберг Д., Скотт К. «Применение объектного моделирования с использованием UML».
- **Практикум:** Галиаскаров Э.Г., Воробьёв А.С. «Анализ и проектирование систем с использованием UML».
- **Visual Paradigm 18.1** - моделирование в ЛР №1, №2, №4 и №5.
- **HTML/CSS** - макеты экранных форм (ЛР №5), исходник в `lr_05-interaction-model/wireframes/`.
- **MDriven Designer** - ЛР №3 (OCL, исполняемая модель).
- **Каталог бизнес-правил и User Story** - лекция 7; материалы GetAnalyst - интеграционные Use Cases (ЛР №4).

## Карта лабораторных работ

1. **Концептуальная модель классов** - предметная область: классы + связи + кратности.
2. **Варианты использования** - акторы и их задачи (use case diagram + описания).
3. **Проверка модели и OCL** - исполняемая модель, ограничения, навигация.
4. **Спецификация вариантов использования** - подробные сценарии и диаграммы деятельности.
5. **Модель взаимодействия** - раскадровка экранных форм, системные диаграммы последовательности, системные операции.
6. **Диаграммы робастности (пригодности)** - связка требований и дизайна: boundary / control / entity объекты.
7. **Диаграммы автоматов (состояний)** - жизненный цикл объекта по состояниям.
